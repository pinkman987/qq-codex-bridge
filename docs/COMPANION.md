# 陪伴聊天：记忆、连续输入与语音

> 当前界面说明（2026-10-16）：语音/Omni 配置入口暂时移除，以下语音章节用于旧配置兼容说明；普通保存保留旧参数与密钥。定时主动私聊已移除。新手请先阅读 [当前使用说明](USAGE.md)。

本页介绍主分支源码中的陪伴与多模态更新，现有 v0.2.0-beta.1 Release 安装包不包含这些新增改动。后台更新需真正重启桥接程序；仅刷新页面或复用已运行进程不会加载新的服务端代码。旧后台会提示升级，保留页面输入并阻止提交新增配置；更新前请备份本机 config.json 与 state/，停掉旧桥接后再启动。

## 记忆与历史预算

上下文由人设、带来源的长期记忆与摘录、最近对话组成。默认保留最近 15 轮已完成对话；更早的用户内容进入最多 16 条摘录，明确自述形成的长期事实独立保存，管理员可以修正。连续未回复输入也有存储边界，避免历史无限增长。

「记忆与话题」可设置 1–30 轮及 2000–20000 字符历史预算，默认 6000 字符。构造请求时优先相关记忆和最近消息；人设、当前消息与规则另外保留。字符数不等于 token，较小预算可能舍弃近期长消息细节。历史仅作背景，当前消息单独标记；不会为清理旧输出而改写原历史文件。

## 连续消息与回复

### 理解梗与用语教学

普通闲聊的 Codex、兼容 API 与 Omni 通道均加入语境判断：结合最近对话区分反话、谐音、夸张、引用、玩梗和认真提问。认识的梗优先自然接话，用户询问含义或出处时才解释；不照搬固定段子、假装搜索或编造最新出处。图片梗只能结合实际收到的图文理解；Omni 还可使用下文的按需搜索与图片追问功能。

管理员可以在机器人私聊发送 `/梗 词语 | 含义或使用场景`（也支持全角 `｜`）。例如 `/梗 三赢 | 在我们聊天里，三个方面都倒霉时的反话；真正三方获益时仍按字面理解`。这是一条本会话约定，不代表该词在所有场景的通用含义。梗词最多40字符、释义最多180字符，作为有来源的手动记忆保存；同名梗再次教学会更新，不重复新增。不额外调用模型，不执行释义中的命令。

教学只影响管理员当前私聊。控制台「记忆与话题」选择对应会话，可修改或删除梗释义；给群添加内部梗时，选择该群并手动补充“词语在本群的含义及使用场景”，私人约定不会自动传播到群或其他会话。教学与普通记忆共用80条存储上限和历史字符预算，关联梗优先检索。闲聊的人设与工作任务权限保留，工作模式不套用接梗规则。

这是提示词与有来源记忆的改进，没有训练或微调模型；理解效果仍受模型和上下文影响。当前检验使用隔离模型/QQ mock，验证教学、检索、通道与权限流程，不把 mock 返回的句子当作真实模型懂梗的证据。

「聊天风格」的连续消息聚合窗口默认 700 毫秒，最长聚合等待默认 2000 毫秒；这些等待不包括排队、媒体预处理和模型推理。0 毫秒表示尽快处理，不保证即时回复。聚合按会话隔离，同一会话推理期间的新输入进入下一批。消息先入队再处理图片或语音，避免较慢的媒体被后来的文字超越。

运行统计记录聚合批次、收到的消息数和相对逐条聊天请求减少的次数。重写、图片理解和语音识别可能增加调用，聚合统计不能直接换算费用、token 或响应速度。

明显重复上轮回复时最多重写一次。重写后仍相似但有安全正文时会发送，避免直接对话被过滤后一直无回应。普通私聊或被 @ 时如果完全没有有效正文，会提示这一轮生成失败；主动插话仍可保持安静。只有真正发送成功才记录已回复。

旧行首 `[发群]` 指令不会被执行或作为普通回复发送；引用、解释和代码示例保留。管理员当前回合明确授权的结构化转发继续受白名单验证。

## 原生 Omni 聊天

旧版界面曾在「聊天模型 → Omni 与语音接口」选择「Qwen Omni · 直接听音频并回答」，或点「使用 Qwen3.8 Omni 配置」。填写所属百炼业务空间与地域的 OpenAI 兼容基础地址、`qwen3.8-omni-flash` 和对应 API Key。北京业务空间地址形如 `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`，不是 Anthropic 路径。预设只切换模式和模型，不复制密钥。点「测试 Omni 连接（仅固定文字）」核实地址与模型，再启用并保存。

启用后，群聊、管理员闲聊、主动私聊与讲题统一使用这个 Omni 配置，上方的普通聊天模型暂不参与这些请求；蒸馏仍使用原聊天模型，工作任务仍使用 Codex。关闭 Omni 后恢复原聊天模型。原有配置兼容：语音默认关闭，旧语音配置仍为转写模式。费用归独立 Omni 密钥所属账户，普通文字和主动判断也会消耗其额度。

QQ 语音经 OneBot `get_record` 转换为 WAV，再以 `input_audio` 随当前消息交给模型；不先调用语音转写服务。兼容网关返回转换后文件路径或内联 Base64；SnowLuma 的转换结果在 `base64` 字段，`file` 可能仍指原始 SILK，优先读取并校验转换结果。不会下载任意音频 URL。文字、允许处理的图片与语音可以合并为一个当前回合，继续携带人设和有预算的历史记忆。仅处理管理员私聊及同一消息里 @ 机器人的群媒体，未 @ 的群媒体不上传。单条消息最多两段音频、两张图片；内联音频仅 WAV/MP3、单文件最多 7 MB，整轮内联媒体另有约 9.5 MB 的请求预算。较大文件会提示失败，不猜内容。只有音频且转换失败时直接提示「音频没传到模型」，不调用模型假装听过。

调用 `POST /chat/completions`，使用流式接收、文字输出及 `reasoning_effort: none`。本机最多等待 120 秒；完整接收后才发 QQ 气泡，流中断、超时、错误或被取消不会发半句。此接口不接入 realtime 协议、实时通话、视频解析或语音合成。参见[百炼 Omni 文档](https://help.aliyun.com/zh/model-studio/qwen-omni)及[业务空间地址说明](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)。

音频 Base64 不保存到会话历史或日志。模型返回的音频文字理解仅作为带编号、标为「模型生成未核对」的近期背景，供后续接话；不会自动学习为长期事实，也不能授权工作或群转发。真正发出回复后才保存这份理解。若模型未提供可核对的理解，历史只保留「曾发送语音」的说明。普通文本的记忆学习规则保持不变。

## 按需搜索与图片追问

「聊天模型 → Omni 与语音接口」增加两个独立开关：

- **允许按需联网搜索**：默认关闭，需启用百炼 `qwen3.8-omni-flash`。复用 Omni 密钥，不新增另一家搜索服务。管理员闲聊、被 @ 的群消息和讲题请求携带 `enable_search: true`、`search_options: { search_strategy: "agent" }`，让服务根据当前问题决定是否检索。可以问“这个梗是什么意思，搜一下”“查一下今天的更新”。不承诺每轮都搜索；陌生梗、需要查证的信息由模型判断，失败/无证据时要求如实说明。其他引擎不会收到 Qwen 专属参数，切换引擎前先关闭搜索。固定文字连接测试、记录蒸馏、定时主动私聊、普通群插话和管理员工作引擎不挂载此搜索能力。
- **图片追问时重新看图**：默认开启，仅 Omni 生效，不依赖搜索开关。发图后说“再仔细看看”“图里的这个”或紧接着说“搜一下”，会重新附上同会话、同发送者最近10分钟内的图，并明确说明是此前图片，按当前问题重新判断。明确的新话题（如“搜一下明天天气”）不附旧图。新图替换旧图，上传失败不回退旧图；超时、重启、换引擎/搜索设置、改人设、暂停桥接和 `/reset` 清除。缓存只在内存，不保存URL/Base64到历史，也不下载额外媒体；最多16个会话条目、单条8MB、总24MB，每条最多两张。QQ原图链接失效或缓存不可用时需重新发图。追问仍受整轮媒体约9.5MB限制。

配置示例：

```json
"search": { "enabled": false, "imageFollowup": true }
```

检索线索来自图片上的文字、标志、物品、游戏界面、作品和用户明确提供的名字；不实现根据人脸辨认真实人物或确认身份的功能，也不是反向图片检索。网页是第三方资料，不能改变人设/权限，不能授权转发或执行工作；提示模型不要用密钥、QQ号、私聊原文及私人记忆作搜索词。

原生搜索由百炼服务端执行，可能增加模型耗时、token及服务商检索收费，费用归 Omni 密钥所属账户。模型请求超时仍为120秒，完整成功后才发送回复，配置变更会取消迟到候选。控制页只显示“允许搜索”，不虚报已执行的搜索次数：当前 Chat Completions 兼容协议不返回程序可验证的来源列表和搜索角标。模型有实际服务来源才引用，否则不编造来源/网址，不把自述“搜到”当程序验证。相关限制见[百炼搜索文档](https://help.aliyun.com/zh/model-studio/web-search)与[Omni 搜索参数示例](https://help.aliyun.com/zh/model-studio/qwen-omni)。搜索不能保证每次答对；图片追问会重新提供实际图片，不保证修正后的判断必然正确。

`test/search.test.mjs` 覆盖请求参数、旧配置迁移、密钥保留、开关保存、图片重看与新话题、替换失败、过期/清除/缓存预算、私聊和群/发送者隔离、未 @ 媒体保护、主动消息不搜索、配置变更迟到回复拦截及未授权转发保护。使用隔离mock，验证流程和边界，不能视作真实上游检索效果实测。

## 独立语音转写接口

在「聊天模型 → Omni 与语音接口」选择「语音转写 · 原聊天模型回答」，填服务地址、模型名及独立 API Key。默认关闭，可以先保存地址和模型，稍后填密钥再启用。语音密钥不回显，不自动复用聊天密钥；更换服务来源需要重新填写。

服务应支持 OpenAI 兼容的 multipart `POST /audio/transcriptions`（`file`、`model`），返回 `{ "text": "识别文字" }`。聊天接口可用不代表支持此接口。[官方语音转写格式](https://developers.openai.com/api/docs/guides/speech-to-text)。

网关需支持 [`get_record`](https://github.com/botuniverse/onebot-11/blob/master/api/public.md) 及 `out_format: wav`，返回本机可读的转换后路径，或像 SnowLuma 一样返回转换后的 `base64`。程序校验格式及大小后上传到所填服务，不会下载任意音频 URL。支持通过文件内容检查的 WAV、MP3、Ogg、FLAC；单文件不超过 20 MiB，识别请求最多等待 30 秒，每条消息最多处理两段音频。OneBot 接收帧最多32 MiB以容纳转码音频Base64，音频本身仍遵守前述较小上限。实际格式兼容性由网关及识别服务决定。

开启后处理管理员私聊语音和被 @ 的群语音；普通群语音不主动转写。识别失败不会猜测内容，会请对方补充文字。转写进入当前聊天上下文，回复仍为文字，不包含语音合成或 Fish Audio 接入。识别费用由语音密钥所属账户承担，转写后的文字还会发送给聊天模型；语音调用单独计数，未提供 usage 时不估算 token。

## 验证与基准

`npm test` 使用隔离 QQ/模型/语音 mock，覆盖连续输入、媒体顺序、重复改写、转发边界、记忆预算、密钥隐藏、跨服务密钥保护，以及转写和原生音频到文字回复的完整模拟流程。Omni 测试还覆盖分包中文、流中断、取消、混合媒体单次调用、模型切换后禁止迟到回复、音频不落盘及工作模式不执行纯语音任务。测试不发送真实 QQ 消息或调用付费模型。固定文字连接测试成功仅证明服务可调用，真实 QQ 语音转换与音频理解仍须用实际语音验收。

`node scripts/benchmark-companion.mjs` 使用合成数据比较无限历史与受预算约束的历史，并验证连续输入聚合。当前样例：80 轮完整历史 69101 字符，预算内历史 3538 字符，保留相关长期事实；30 条输入分为 10 个连续批次，只触发 10 次聊天请求。这是合成字符/调用测试，不能作为真实 token 降低 45% 或回复提速 40% 的证据。真实上游语音接口尚待配置密钥后验收。

## Codex 闲聊联网搜索（2026-10-14）

在控制台「聊天模型」选择「Codex 登录账户」，关闭 Omni 原生聊天，保留「允许按需联网搜索」，再保存并应用。此项使用现有 Codex 引擎的托管搜索，不需要另填 Omni 搜索密钥；是否实际搜索由模型按当前问题决定，并受 Codex 账户及管理配置限制。

仅用户当前私聊、被 @ 的群消息和讲题允许搜索；普通群聊插话不搜索。Codex 的闲聊仍为只读本地沙箱，命令、文件操作、插件与 MCP 工具保持关闭。网页内容不能扩大工作或转发权限。搜索开关关闭时不提供搜索工具，不宣称已经联网。

新版前端会检查后台 `codexSearch` 能力；旧后台需要重新启动桥接后才能保存 Codex 搜索配置。不要只双击启动器复用旧进程。此功能是文字线索联网搜索；图片追问重新附图仍由 Kimi/Omni 提供。

程序仅根据实际完成的 Codex webSearch 事件记录搜索工具次数，不能把“允许搜索”或模型自述视为已搜到结果。完整真实检索质量仍需要在聊天中验收。

Codex 启动时会用当前 CLI 和登录方式刷新模型目录，避免旧缓存默认模型不兼容。一般将「工作空间 → 模型名称」留空，使用当前目录的默认模型。目录只是候选列表，真实调用能否完成仍以服务实际响应为准；模型不支持时给出固定中文提示，不显示上游原始 JSON。
