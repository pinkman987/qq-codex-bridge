# Windows 首次安装

本版本面向 Windows 10/11 本机运行。需要自己准备机器人 QQ、管理员 QQ，以及一个可用的聊天模型。电脑关机或程序退出后，机器人停止工作。

## 1. 准备运行环境

从 [Node.js 官方网站](https://nodejs.org/) 安装 Node.js 22.13 或更新版本。打开终端运行 `node --version` 和 `npm --version` 确认安装成功。使用发布 ZIP 时，解压整个文件夹后再启动；不要在压缩包预览窗口里运行。

双击 `start.cmd`。首次启动会使用锁定文件执行 `npm ci` 下载依赖，需要联网。控制页自动打开；终端需要保持运行。下载源码的用户也可以在项目目录运行：

```powershell
npm ci
npm start
```

第一次会打开账号连接的三步引导，桥接默认暂停。控制页地址带有随机登录令牌；直接打开不带令牌的地址会无法读取配置，请用启动时打开的完整地址。

## 2. 选择模型

| 方式 | 要准备什么 | 可用功能 |
| --- | --- | --- |
| Codex 登录 | 安装 Codex CLI 并完成自己的官方登录 | 聊天和管理员项目任务 |
| OpenAI 兼容接口 | 服务地址、模型 ID、API Key；本机模型可不填 Key | 聊天、主动聊天、记录蒸馏；图片功能取决于模型 |

兼容接口：在「聊天模型」填写配置并点「测试模型连接」，成功后保存。测试会向所填服务发送一条固定测试文字并消耗对应账户额度。API Key 不会返回给网页；留空保留已保存值。更换服务地址时请重新输入该服务的 Key。

Codex：按其 [官方仓库安装说明](https://github.com/openai/codex) 安装 CLI，然后运行 `codex login`。本项目协议基线为 0.153.4；其他版本先用 `npm run doctor -- --engines --work` 检查兼容性。首次聊天前会检查模型目录，缺失时尝试只初始化，不发起模型推理；失败会提示处理方法。

## 3. 登录机器人 QQ

从 [SnowLuma 官方发布页](https://github.com/SnowLuma/SnowLuma/releases/latest) 单独下载并按其说明安装。本项目不包含 SnowLuma、QQ 或它们的运行文件。阅读并自行确认其条款。

在 SnowLuma 登录 **机器人用的 QQ**。管理员 QQ 是你平时发任务的账号，要填到桥接网页。按 SnowLuma 的当前引导加载 QQ 进程、扫码，并开启 OneBot v11 正向 WebSocket 服务端。

在「账号连接」填管理员 QQ、白名单群号、WebSocket 地址和对应 `accessToken`。例如地址 `ws://127.0.0.1:3001`。连接令牌与 SnowLuma WebUI 密码不同。启用 QQ 桥接并保存；网页应分别显示「设置已保存」和「QQ 已连接」。

管理员私聊 `/help` 验证；群里 @机器人验证。私聊默认是工作模式。**只配置兼容接口聊天时，请先发 `/mode chat`。** 发 `/mode work` 才会使用 Codex 工作引擎。

## 4. 可选功能

- 项目任务：在「工作空间」填写 `项目名=文件夹绝对路径`，目录需已存在。私聊 `/project 项目名` 切换。
- 主动聊天：在「主动聊天」开启。默认北京时间 10:00–22:00、双方安静 2 小时、每天最多 2 次；未回复就不追发。
- 消息库：默认只在桌面、OneDrive 桌面的直接安装目录或一层父目录中寻找。安装在其他位置或有多个 QQ 账号时，填写 `SnowLuma安装目录\data\机器人QQ\messages.db` 的绝对路径。
- 记录蒸馏：支持粘贴、文件、消息库和 Windows 截图 OCR，先校对再确认发送给模型。无 2000 条上限；仍保留单次 64 MiB 和分析时限等资源限制。

遇到问题先在「工作空间」点「检查本机环境」，或双击 `check.cmd`。本机检查不调用模型、不发送 QQ 消息。更多步骤见 [故障排查](TROUBLESHOOTING.md)。
