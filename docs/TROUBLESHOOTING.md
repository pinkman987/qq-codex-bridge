# 故障排查

| 现象 | 检查与处理 |
| --- | --- |
| 找不到 node / 窗口一闪而过 | 安装 Node.js 22.13+ 后重新开终端；双击 start.cmd 或在终端运行 npm start 看错误 |
| 首次依赖安装失败 | 核对网络和 npm 注册表，项目目录运行 npm ci；不要下载陌生的代安装脚本 |
| 端口被占用 | 关闭此前启动的桥接或占用程序；需要并行运行时在 config.json 修改 consolePort，范围 1024–65535 |
| 控制页未授权 / 后台未连接 | 使用启动日志中的完整本机地址，保留 # 后的登录令牌；不要分享该地址。确认终端尚在运行 |
| 已保存但 QQ 没连接 | 保存成功只代表配置落盘。核对 SnowLuma 账号登录、正向 WebSocket 状态、地址和 accessToken。WebUI 密码不是 OneBot 令牌 |
| QQ 重启后断连 | SnowLuma 如果没有自动加载新进程，重新按其流程加载后登录；旧进程成功不代表新进程可用 |
| 配了 API 却提示 Codex 错误 | 管理员私聊默认工作模式，先发 /mode chat。工作任务仍需要 Codex；网页的完整工作引擎检查也是可选项 |
| Codex 尚未登录 | 用本机自己的 codex login 完成登录，然后 npm run doctor -- --engines --work。不要复制别人的 auth.json |
| Codex 模型目录未生成或协议不兼容 | 再运行完整引擎检查；核对 CLI 版本。程序不会退回能操作电脑的群聊配置。可先使用兼容接口聊天 |
| API 401 / 404 / 模型不存在 | 核对服务地址、Key 权限和服务商实际模型 ID。更换地址后重新填 Key；测试会调用模型 |
| 消息库未发现 / 多个消息库 | 在账号连接填机器人账号 messages.db 的绝对路径并保存。也可使用粘贴或文件来源；跨账号不自动猜选 |
| 截图识别不可用 | 需要 Windows 10/11 自带 OCR 与对应语言包。非 Windows 用粘贴或文件导入。长图可分批，单次最多 20 张且需满足像素限制 |
| 确认记录失败 | 至少 10 条，每行一条，单条最多 300 字。条数无上限，但一次确认请求最大 64 MiB |
| 模型超时 | 核对服务状态、上下文长度和单次等待时间。大记录会分块并归并，耗时与额度随记录数增长；总分析最长 30 分钟 |
| 校对中重启后任务中断 | 校对原文只保存在进程内，不会跨重启自动恢复；从原始文件重新导入。最终结果与进度概要保存在 state/ |
| 配置冲突 | 另一页面更新了设置。你的输入保留，先备份草稿，再载入最新配置重新修改 |
| 本地 JSON 文件损坏 | 停止程序，先完整备份 config.json 和 state/；只修复报错的文件，恢复自己的备份。清空 state/ 会丢失会话、记忆、计数及默认项目 |

## 升级与备份

1. 停止桥接，复制整个 `config.json` 和 `state/` 到私人备份目录。`state/projects/default` 也可能包含你的工作成果。
2. 解压新版本到新目录，按 [首次安装](QUICKSTART.md) 安装依赖。不要从旧版本覆盖新代码或 node_modules。
3. 把自己的配置和 state/ 复制到新目录；运行 `npm run doctor` 后启动。
4. 完成测试后再移除旧版本。不要同时运行两份连接同一个机器人 QQ 的桥接。

目前没有自动数据库迁移或跨版本回滚承诺。公开测试版升级前始终保留私人备份。

## 报告问题

提供操作步骤、预期/实际结果、Node/系统/CLI 版本和脱敏错误。删除 QQ 号、群号、API Key、OneBot 令牌、控制页 # 后令牌、聊天原文和本机私人路径。不要上传 config.json、state/ 或整个运行目录。公开 Issue 不适合提交安全问题，见 [安全说明](../SECURITY.md)。
