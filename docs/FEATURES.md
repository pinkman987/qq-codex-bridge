# Codex 接入 QQ：群友 + 私聊助手

一个本机运行的桥接程序。群聊和管理员闲聊使用无操作工具的聊天引擎，可选本机 Codex 登录或第三方 OpenAI 兼容接口；工作任务使用本机 Codex 项目工具。

## 先启动

1. 本机需要 Node.js 22.13+；Codex 聊天和工作任务需要 Codex CLI，兼容接口聊天可不安装。若还没安装 CLI，运行 `npm install -g @openai/codex`，然后 `codex login` 完成官方登录。
2. 双击 `start.cmd`，或在项目目录运行 `npm ci` 后运行 `npm start`。控制页地址会打印在终端。关掉终端会停止桥接。
3. 第一次安装或排错，可运行 `npm run doctor`。默认只检查本地环境，完整登录检查使用 npm run doctor -- --engines --work，不发 QQ 消息，不调用模型。

## 接入 QQ

1. 从 [SnowLuma 官方发布页](https://github.com/SnowLuma/SnowLuma/releases/latest) 获取 Windows 版；已经安装合适的 Node.js 时可使用 Lite 版。解压并按它的引导启动。
2. 先把机器人 QQ 打开到二维码登录页，在 SnowLuma「进程注入」中加载对应 QQ 进程，等状态变为「等待登录」后再扫码，并在手机上确认。登录、设置密码及同意条款由你在其界面完成。
3. 开启 **OneBot v11 WebSocket 服务端（正向 WebSocket）**，地址通常为 `ws://127.0.0.1:3001`。本程序通过同一 WebSocket 收事件和调用发消息动作，不需要 HTTP API。
4. 在桥接控制页左侧选择「账号连接」，填写 **管理员 QQ 号**（你发任务的账号）、**允许接入的群号**、WebSocket 地址及匹配的连接令牌。
5. 按需选择「工作空间」添加项目，例如 `网站=C:\Projects\my-site`；在账号连接中启用桥接，再点底部「保存并应用」。没有配置项目时也可在 `state/projects/default` 创建文件。
6. 保存时间与 QQ 在线状态分别显示。看到「QQ 已连接」后，用管理员账号私聊机器人 `/help`，在群里 @它发文字消息验证。

默认暂停，不会在未填管理员或群号时放行其他账号。QQ 服务未运行时会自动等待重连。

保存按钮始终固定在页面底部，也可按 `Ctrl+S`。错误会标出对应字段；保存失败不会清空你的输入。令牌留空会保留已保存值。其他页面同时改配置时会提示冲突，避免覆盖；「撤销修改」会重新载入最新保存的设置。相同配置再次保存只核对状态，不重启引擎。

如果 QQ 退出账号或重启后换了进程，而 SnowLuma 未开启自动加载，需要重新加载新进程。先停在二维码页，加载 SnowLuma 后再扫码；旧进程加载成功不代表新进程也已加载。连接令牌使用机器人账号配置中正向 WebSocket 端点的 `accessToken`，与 WebUI 的管理员密码不同。

## 两种使用方式

群聊：被 @ 时回应，也会偶尔加入正在进行的讨论。模板默认 8% 判断概率，最短 3 分钟间隔，每群每小时最多调用模型 8 次；已有用户配置保留原值。最初收集至少 3 条群消息后才考虑主动参与。插话功能会消耗所选聊天模型的额度，选择沉默的判断也计入调用次数。插话间隔只限制主动插话，不限制正常聊天的下一句。每个气泡尽量 20 字，按句子分段；内容完整优先，不再硬截断。超过气泡数量上限的尾部合并到最后一条。

私聊：只有管理员账号可用，默认将消息作为工作任务；首次启用主动私聊会切换到闲聊，之后保留你选择的模式。输入 `/mode chat` 改为闲聊，`/mode work` 改回工作。`/projects` 列出项目，`/project 项目名` 切换工作目录，`/stop` 停止任务并取消待处理消息，`/reset` 开启新会话，清空近期对话；长期记忆和待续话题在控制台单独编辑或删除。

连续闲聊默认等待约 700 毫秒合并，连续输入最多合并等待 2 秒。生成回复期间的新消息进入同一会话队列，完成后继续回复；群里新的 @ 也会排队。每个会话最多暂存 30 条待处理消息，超出会明确记录队列已满。工作任务仍逐个处理，不合并文件操作指令。主动判断会避开待处理的私聊。

## 第三方聊天模型

在「聊天模型」选择「第三方 / OpenAI 兼容接口」，填写 Base URL、模型 ID 和 API Key，点击「测试模型连接」，成功后「保存并应用」。一般调用 `POST /chat/completions`；地址路径以 `/anthropic` 或 `/anthropic/vN` 结尾时自动适配 Anthropic Messages 协议。地址可填写 API 根路径，例如 `https://你的服务/v1`，也可填写完整 `/chat/completions` 端点。远程服务要求 HTTPS，本机 HTTP 模型可不填 Key。

密钥保存在本机 config.json，接口和日志不回显；留空保留，勾选「删除已保存的 API Key」可移除。换到另一个服务商地址时需重填该服务的 Key，防止把旧密钥发送到新服务。测试只发送固定测试文字，没有聊天记录，不保存配置。使用该模型后，群聊、闲聊和主动私聊内容会发送到配置的服务；费用归该 Key 所属账户。工作任务始终使用本机 Codex 登录。选回 Codex 后不调用第三方接口。

## 主动私聊

「偶尔来找你聊聊」开关控制后台判断。仅面向管理员、仅闲聊模式生效；工作模式、QQ 离线、正在处理任务时暂停。模板默认关闭，开启后的默认时段为北京时间 10:00–22:00，双方安静至少 120 分钟，判断之间至少 60 分钟，每天最多主动发 2 次。每分钟检查本机条件，满足条件才调用聊天模型；不是到点必发，没有合适话题会保持安静。

先和机器人闲聊几句，后台会保存最多 20 条近期闲聊作为可续接的话题。你没回复就不追发，即使跨天也继续等待；你主动发来新消息会取消尚未发出的主动消息。每天最多调用模型判断「每日消息上限 × 3」次，包含沉默和失败，避免无限消耗。日次数、未回复状态和私聊模式会跨重启保留。`/outreach pause` 暂停、`/outreach resume` 恢复，也可以关闭网页开关并保存。电脑和桥接程序必须运行。

工具审批会以私聊形式发给管理员，用 `/approve 编号` 或 `/deny 编号` 处理这一次操作；5 分钟未答复自动拒绝。助手提问时，用 `/answer 编号 回答` 按题目顺序作答。聊天/群聊永远不接受操作审批。

## 记忆、话题与语气状态

控制台「记忆与待续话题」可按管理员私聊或白名单群查看。私聊只从明确的自述中摘录偏好、称呼等事实，保留原文和时间，不额外调用模型。最新 20 条实际收发记录之外，保留最多 16 条较旧原文摘录；这是一份可核对的摘录摘要，不是模型猜测。回答时选取相关记忆和有限上下文，避免每轮重复发送无限历史。各群与私聊独立保存。

记忆可以手动添加、修正、删除。自动内容最多 80 条，手动设置不会被自动学习覆盖；删除和修正留下阻止原文再次学习的标记。语气和聊天活跃度随对话轻微变化，约两小时逐渐衰减回当前时段的基线，重启后保留。这些状态只影响说话方式。

明确提到的考试、面试、项目等未来计划会进入待续话题，也可手动添加。最多 40 条；完成后关闭，或者在页面点「结束话题」。话题到期后才可续接，同一个话题一天内不重复问，累计最多追问两次。主动发送仍受你原来的时段、静默时间、每日上限和未回复不追发约束；普通回复或旧话题的重复建议会被拦截。主题提取采用有限规则，复杂计划可手动补充或修正。

## 代发与运行统计

只有管理员当前私聊中的明确发群请求才能授权代发，例如「帮我把晚安发到群里」。模型须给出单独的结构化动作，经白名单和长度验证后执行。普通正文、引用 `[发群]`、解释标记、群成员请求都不会触发代发；旧标记解析函数仅保留兼容，不再作为执行入口。

页面显示今日调用次数、失败次数、平均模型耗时、待处理消息和服务返回的输入/输出 token。按私聊、群聊、主动考虑、工作、蒸馏和连接测试分类，保存最近 30 条调用与 14 天汇总，不记录提示词或密钥。服务未返回 usage 时显示未知；Codex 的本机协议在此版本未接入 token 统计，只统计调用和耗时。API 输入/输出用量使用服务返回字段，Anthropic 输入包含缓存读写。[OpenAI token 说明](https://developers.openai.com/api/docs/guides/token-counting)，[Anthropic 缓存用量说明](https://platform.claude.com/docs/zh-CN/build-with-claude/prompt-caching)。

人设预设、聊天记录蒸馏与本机截图 OCR 保留。蒸馏结果仍通过可编辑的人设区应用，不自动混入新记忆库。

长截图 OCR 按本机引擎的尺寸上限自动分段，保持原文字大小，并用重叠边界避免截断文字。可累加最多 20 张图；聊天记录无条数上限，不再抽样到 2000 条。粘贴、文件与截图整理出的全部记录进入校对，SnowLuma 默认读取所选会话的全部记录。图片宽度仍需在本机 OCR 上限以内，总像素不超过2亿，导入与确认每次提交最大 64 MiB（图片含 Base64 编码）。至少需要 10 条记录，单条保留原有长度规则。

蒸馏现在按任务运行：本机识别/整理后先显示可编辑的聊天记录，**确认校对前不会调用模型**。确认后最多分析 30 分钟；第三方 API 的单次分析最多等待 3 分钟。页面可取消任务，刷新后会找回任务进度和完成结果。任务概要与最终结果保存在本机 `state/distill-job.json`，新任务的原始 OCR 校对文字只在当前进程内保留；若桥接在校对或分析时重启，页面会明确提示任务中断。生成的 [回忆] 段需要核对并勾选确认才能并入人设。OCR 在本机完成，确认后才会把选取的聊天文字发送到已配置的模型服务。

超过 100 条时按每块 100 条、最多 4 路并行提取观察，每条输入记录都会进入分块。观察超过 200 行时，先以最多 200 行一批分层归并，再生成最终风格，避免把无限增长的观察塞入同一次模型请求；归并是模型摘要，会压缩细节。过程显示归并轮次和批次，取消、超时和失败仍会停止整项任务。记录越多，模型调用与处理时间越多，分析总时限仍为 30 分钟。

分块遇到普通 HTTP 400 或服务端 5xx 时仅重试一次，持续失败会停止，不猜测成内容审核。服务明确返回内容拒绝代码时可拆分定位并排除被拒记录，最终显示排除数量，结果只基于其余记录；每块定位最多 32 次调用，达到上限明确报错。[阿里云官方错误码说明](https://help.aliyun.com/en/model-studio/error-code) 区分普通参数错误与 DataInspectionFailed/data_inspection_failed，单凭 HTTP 400 无法区分。

控制页使用 [Pico CSS 2.1.1](https://github.com/picocss/pico) 作为表单基础，以及 [Tabler Icons](https://github.com/tabler/tabler-icons) 的 MIT 许可 SVG 图标。素材由本机提供，不依赖 CDN，许可与来源见 `THIRD-PARTY-NOTICES.md`。界面采用深色侧边导航、八个独立设置分区、状态卡片、操作指南和固定保存栏。手机宽度下导航变为横向滚动，表单自动调整列数；切换分区保留草稿，保存校验会自动定位错误所在分区。人设预设管理可以折叠，蒸馏提供导入／校对／提炼三步引导、可恢复的任务进度与取消按钮。

## 数据与权限

- 各群、管理员闲聊、各项目使用独立会话；Codex 会话映射保存在本机 `state/sessions.json`，兼容 API 按服务地址和模型隔离会话，最近历史保存在 `state/api-chats.json`。不会自动接管桌面里已有聊天。
- 群聊使用单独的 Codex 进程，并从本机模型目录生成禁用 shell、文件编辑、图片读取、浏览器、插件、MCP 和代理的聊天配置；同时使用只读沙箱，拒绝所有操作审批。工作引擎使用项目写入沙箱，审批交给管理员。
- 两个引擎都禁用第三方插件和用户 MCP，工作引擎保留 Codex 内置项目工具。它们不会修改你的全局 Codex 配置，也不会复制登录凭证。
- 白名单群与管理员闲聊的有限上下文、记忆、来源、语气及待续话题保存在 `state/sessions.json.social.json`；回复时相关资料会发给所选聊天服务。主动私聊等待回复状态及次数保存在 `state/sessions.json.outreach.json`，用量汇总保存在 `state/sessions.json.metrics.json`。运行日志只记录状态，不记录聊天原文。Codex 使用账户额度，第三方使用所填 Key 的服务额度。
- 支持文字与 QQ 表情；兼容视觉接口可理解有限图片。语音不会转写，文件、合并转发和复杂引用尚未提供完整解析。管理员可用 /讲题 或 /ti 进入讲题模式，图片讲题需要视觉接口。工作权限是 Codex 的项目沙箱边界，不是整个系统的容器隔离。
- 控制页仅监听 `127.0.0.1`，API 需要本地随机令牌，不显示已保存的 OneBot 令牌或模型 API Key。
- 修改人设、插话节奏、主动私聊时段即时更新，保持 QQ 连接与当前项目；下一轮使用新设置。更换聊天模型停止旧聊天引擎，保留待处理消息，工作引擎保持；改变工作模型或当前项目路径会停止受影响的工作任务。账号、连接信息或启用状态改变才重连 QQ，移出白名单后不再发送迟到回复。

## 文件与维护

`config.json` 存放实际配置，`config.example.json` 是模板。`state/` 存放会话映射、控制页令牌、聊天用模型目录及默认项目，请保留。不要公开包含这些文件的打包目录。

升级 Codex CLI 后先运行 `npm run doctor`；若协议或模型目录不兼容，程序会报错，不会降级成能操作电脑的群聊引擎。当前实现按 Codex CLI 0.153.4 的本机协议生成文件核对。

自测：`npm test`，使用模拟 Codex、QQ 与本机 API 服务，不发送真实 QQ 消息。接口文档：[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[Chat Completions 格式](https://developers.openai.com/api/docs/guides/migrate-to-responses)。
